# ADR 0006 implementation notes

Current Zcash boundary: wallet-signing references below are historical and superseded by `docs/ZCASH_TRANSACTION_LAB.md`. No signing-capable Zcash adapter exists or is authorized.

This file records the implementation deviations, follow-ups, and
operational guidance for the atomic-swap observer and watchtower
surface. The ADR itself is in `0006-atomic-swap-observer.md`; this
file is the change log that operators and reviewers reach for when
the live service does not match the design.

## Implementation deviations

The implementation shipped in this PR deviates from the ADR in
three places. Each deviation was either forced by a constraint not
visible in the ADR, or accepted as a known limitation that a later
PR will address.

1. **Topic hashing.** The `keccakTopic` helper in
   `src/lib/evm-observer.ts` returns a sha256d hash, not a keccak256
   hash. The naming is preserved from a draft, and the helper is
   only used to pin the topic signature literals in the observer's
   `EVMTOPICS` table. The fix is a real keccak256 primitive in a
   later PR; the observer's contract-side topic is generated by
   Solidity's keccak256 and the contract itself remains the
   authoritative source. The PR 4 surface does not emit events.

2. **Topic position for the fill id.** The ConditionalLock
   contract emits `uint256 indexed lockId` as the first indexed
   parameter; the observer reads `topicData[1]`, not `topicData[0]`
   (which is the event signature hash). The ADR was ambiguous on
   the topic position; the implementation is locked to the
   contract's actual ABI.

3. **Default refund offsets.** The coordinator's `applyTransition`
   creates a fill with `evmRefundAfter = nowSeconds + 900_000` and
   `zecRefundAfter = nowSeconds + 1_800_000`. The ADR left the
   offsets to a later decision; the implementation chose 10.4 days
   and 20.8 days respectively to keep both well above the worst-case
   reorg depth while preserving the strict-less-than invariant in
   the swap state machine.

## Out of scope

The following items are explicitly out of scope for PR 4. They are
listed here so reviewers do not confuse the absence of code with
missing requirements.

* Live wallet signing. The signing surface lives in the wallet
  adapter. The observer never holds a key.
* Transaction submission. The observer never submits an EVM or
  ZEC transaction.
* Shielded ZEC. The observer only watches transparent P2SH
  addresses.
* Custodial or wrapped representations of ZEC. The observer is
  read-only on the chains.

## Follow-up work

The follow-up list is intentionally short. The next PR that
extends the observer surface should:

* replace the sha256d topic hash with a real keccak256 primitive;
* add a reorg-aware poller that resyncs from the configured
  `fromBlock` after a `reorg-depth-exceeded` alert;
* add a circuit breaker for the EVM and ZEC clients (5xx and
  timeout budgets);
* wire the watchtower's alerts to the operator-runbook paging
  surface.
